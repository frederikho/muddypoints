# CLAUDE.md

Guide for Claude (Claude Code, or Claude Web with this repo connected). Humans: see README.md.

## What this is
Muddy Points: lecture feedback boards, named after the "muddiest point" classroom technique. Staff upload slides (PDF/images) to a board; students open the public board link, get a random anonymous name and comment on and like slides; staff export slides and comments as PDF and swap in the next week's material.

## Architecture
- `frontend/`: static vanilla JS (ES modules, **no build step, no npm**). Deployed to GitHub Pages by `.github/workflows/deploy.yml`. During deploy `frontend/js/config.js` is overwritten with the API URL; keep `apiBase: ""` in the repo (that means same origin for the dev server).
  - `index.html` + `js/app.js`: dashboard SPA (login, register, forgot, `#/` spaces, `#/space/<id>`, `#/account` with API keys)
  - `board.html` + `js/board.js`: public board (slides, comments, likes, staff settings side panel behind ⚙, 20 s auto-refresh)
  - `reset.html`: password reset target (`?token=`)
  - `img/`: logo and favicons, generated from the source artwork by `scripts/make_logo.py assets/logo-source.jpg` (crops, removes the white background; needs Pillow + numpy locally, not at runtime)
  - `js/api.js`: `cogMenu()`/`menuItem()` (⚙ popover menus), `backgroundPicker()`, `avatar(userId)` (deterministic abstract SVG avatars), fetch wrapper, session in localStorage (`muddypoints.session`), `el()` DOM helper, toasts, and **frontend error reporting** to `/api/client-log`
  - Anonymous identity: localStorage `muddypoints.identity` `{anon_id, name, token, expires_at}`, replaced after 7 days
- `backend/src/muddypoints/`: one Lambda (`muddypoints.handler.lambda_handler`) behind a **Lambda Function URL** (no API Gateway, so there is no 30 s limit; timeout is 300 s)
  - `handler.py`: entry point; routes `/mcp*` to `mcp.py` and everything else to `routes.py`; request logging and error handling
  - `routes.py`: REST endpoints (`/api/...`), thin wrappers only
  - `mcp.py`: MCP server (stateless Streamable HTTP, JSON-RPC, hand-written, no SDK); thin wrappers only
  - Business logic, shared by REST and MCP: `users.py` (accounts, reset, API keys), `spaces.py` (spaces, members, **roles**), `boards.py` (boards, slides, comments, likes, public view), `uploads.py` (presigned uploads, URL import, append/replace), `media.py` (S3, PDF/image → JPEG via PyMuPDF, safe downloads), `export.py` (PDF export, archive, clear), `applogs.py` (CloudWatch query), `identity.py` (anonymous names), `mailer.py` (Brevo, SES fallback, or log-only)
  - Infrastructure helpers: `config.py` (env settings and limits), `db.py` (DynamoDB helpers and key schema), `aws.py` (cached boto3 clients), `auth.py` (PBKDF2, HMAC-signed tokens), `http.py` (Request, Router, ApiError), `log.py` (JSON logging)
  - `data/names.txt`: 779 funny names, generated by `scripts/generate_names.py`
- `template.yaml`: SAM. DynamoDB table (PITR on), S3 bucket (versioned, lifecycle), log group, Lambda and Function URL. `infra/github-oidc.yaml`: one-time deploy-role bootstrap.

## Naming
Users see **Workspace → Board → (Session) → Slides/Comments**, plus shared **Files** per workspace. In code and the database a workspace is still called a **space** (`spaces.py`, `SPACE#<sid>`, `/api/spaces/...`). The MCP layer exposes it as `workspace_id` (outputs are rewritten from `space_id`). A **board is one course** with one public URL for the whole semester; its content changes over time.

## Permission model (enforced in `spaces.require_space` / `boards.require_board`)
- `owner`: everything.
- `editor`: everything **except** deleting the workspace, changing roles, inviting owners and removing owners. Editors may delete boards, slides and comments, replace and clear boards, revoke invites, remove editors, and leave.
- Non-members get **404** (not 403) for workspaces and boards so that ids don't leak. The public board view (`GET /api/boards/<id>`) is open to everyone.
- Comments can be deleted by their author (anonymous or not) and by any workspace member.
- Locked boards: non-members can't comment or like; staff still can.
- A workspace always keeps at least one owner.
- **Superadmin** (the platform operator): emails in the `SUPERADMIN_EMAILS` GitHub **secret** (never in the repo) → `admin.py`. Only counts when the account's email is **verified**. Gets a read-only overview of all workspaces (`GET /api/admin/spaces`, `#/admin` in the dashboard, with member emails); everyone else gets 404. It does not grant access to workspace contents or write rights, and has no MCP tool.

## Email
Registration sends a verification mail (signed stateless token, 7 days, `verify.html`); access is **not** restricted before verification. All mails go out as plain text plus an HTML twin with clickable links (`mailer.to_html`). Brevo answers 201 and rejects bad senders / blocked IPs **afterwards**, so check Brevo's event log (or run the opt-in `tests/test_brevo_live.py`) rather than trusting "email sent" in our log. `MAIL_FROM` must be a Brevo-verified sender; in Brevo disable the unknown-IP blocking (Lambda has no fixed IP).

## Schedules (`schedule.py`, `notify.py`)
- A board shows a sequence of **sessions** (`BOARD#<bid>/SESSION#<id>`: workspace file + `starts_at` in UTC, status `planned → switching → live → done` / `skipped` / `failed`). Board META has `timezone` (default `Europe/Berlin`) and `next_switch_at`.
- `schedule.advance(board_id)` does a switch: archive the current slides and comments (PDF), publish the file (`uploads._ingest` as the user "Schedule"), reopen comments, mark statuses, and email staff. A conditional update (`planned → switching`) makes it run **exactly once**.
- It is triggered by **EventBridge Scheduler** every 5 minutes (`template.yaml` → `ScheduleV2` event → `handler` with `{"source": "muddypoints.scheduler"}` → `run_due`, using GSI1 `SCHED` items) and on **every board page load** when `next_switch_at` has passed.
- Empty board plus planned sessions → the view returns `upcoming` → "Coming soon" card.
- Emails on every content change (manual replace/clear and scheduled switch) go to all workspace members **including the person who made the change** (changes via Claude need a confirmation), except people who opted out per board (`BOARD#<bid>/NOTIFYOFF#<uid>`).
- Archive PDFs are only created when the outgoing material has comments.
- Times: the API accepts local `YYYY-MM-DDTHH:MM` (board time zone) or ISO with offset, and returns `starts_at` (UTC) plus `starts_at_local`. Uses `zoneinfo` + the `tzdata` package.

## Feedback
`POST /api/feedback` (footer link "💡 Feedback or feature idea" on every page) stores the message in DynamoDB (`PK=FEEDBACK`) and mails it to `FEEDBACK_EMAIL` (GitHub **secret**; never put the address in the repo). Honeypot field `website`, max 5 per IP per hour.

## DynamoDB single table (PK / SK), GSI1 = GSI1PK / GSI1SK
```
USER#<uid>        PROFILE               user_id,email,name,pw_hash,pw_version
USER#<uid>        APIKEY#<key_id>       hash,label,prefix,created_at,last_used_at
EMAIL#<email>     EMAIL                 user_id                      (uniqueness)
APIKEY#<sha256>   APIKEY                user_id,key_id               (lookup)
RESET#<sha256>    RESET                 user_id,ttl
SPACE#<sid>       META                  space_id,name
SPACE#<sid>       MEMBER#<uid>          role            GSI1: USER#<uid> / SPACE#<sid>
SPACE#<sid>       INVITE#<email>        role            GSI1: INVITE#<email> / SPACE#<sid>
BOARD#<bid>       META                  name,space_id,locked   GSI1: SPACE#<sid> / BOARD#<bid>
BOARD#<bid>       SLIDE#<slide_id>      key(S3),position,width,height,source,likes
BOARD#<bid>       COMMENT#<sortable_id> slide_id,text,author_name,author_key,is_staff,likes
BOARD#<bid>       LIKE#<target_id>#<viewer_key>   target,viewer   (viewer_key = u:<uid> | a:<anon_id>)
```
Workspace files (`library.py`): `BLOB#<sha256>/META` (global, one per distinct PDF), `SPACE#<sid>/FILE#<file_id>` + `SPACE#<sid>/FILEHASH#<sha256>` (dedup per workspace), `DROP#<sha256(token)>/DROP` (upload links), `BOARD#<bid>/HIST#<sortable_id>` (board history). Every PDF that goes on a board (panel upload, URL import, publish) is also registered as a workspace file.

S3 layout: `blobs/<sha256>.pdf` + `blobs/<sha256>.text.json` (content-addressed files + extracted text), `uploads/<bid>/…` and `uploads/drop/…` (raw uploads, expire after 1 day), `boards/<bid>/slides/<id>.jpg`, `exports/<bid>/…pdf` (expire after 7 days), `archive/<bid>/…pdf` (kept).

When you add an access pattern that needs a new index, add it to **both** `template.yaml` and `localinfra.py` (tests and the dev server use the latter).

## MCP server
Connector URL: `<ApiUrl>/mcp/<api key>` (or `POST /mcp` with `Authorization: Bearer <api key>`). Each user creates keys in the web UI under Account. Tools run with that user's permissions.

| Tool | Purpose |
|---|---|
| `whoami` | current user and workspaces |
| `list_workspaces`, `create_workspace`, `rename_workspace`, `delete_workspace`* | workspaces |
| `list_members`, `invite_member`, `set_member_role`*, `remove_member` (owners only for owners) | sharing |
| `list_boards`, `create_board`, `get_board`, `update_board` (name, locked, background), `delete_board` | boards (backgrounds: `boards.BACKGROUNDS`, CSS `.bg-<id>` in `style.css`, picker list in `api.js`; keep all three in sync) |
| `list_comments`, `delete_comment` | comments |
| `import_slides_from_url` (mode append/replace) | load a PDF or image from a URL (Drive and Dropbox share links work) |
| `replace_board_material` | weekly rotation: archive PDF, clear, import new material from URL |
| `create_upload_link` (hours, note) | **no-login upload page** (`drop.html#<token>`) for a workspace: user drags PDFs in → workspace files. The standard way to receive files from users |
| `list_files`, `read_file` (from_page, to_page, max_chars), `publish_file` (mode), `delete_file` | workspace files: overview (title, pages, outline, `published_to`), paginated text, put on a board |
| `get_schedule`, `set_schedule` (replaces planned), `add_session`, `update_session`, `remove_session` | board schedule (sessions with local times); conventions are in the server instructions in `mcp.py` |
| `set_notifications` | per-board change emails on/off for the current user |
| `view_file_page` | a PDF page as an image (scanned slides, diagrams) |
| `get_board_history` | what was put on a board when (file ids) → reuse material from earlier weeks/semesters |
| `get_upload_link` (replace) | link that opens the board's upload panel (`#upload` / `#upload-replace`); **the way to handle files attached in claude.ai chats** (their sandbox can't reach S3) |
| `prepare_slide_upload` → PUT → `confirm_slide_upload` | direct upload via presigned S3 URL, only for clients with open network (e.g. Claude Code) |
| `reorder_slides`, `delete_slide`, `clear_board` | slide management |
| `export_board_pdf`, `list_board_archives` | PDF of slides and comments (1 h download links) |
| `get_logs` (minutes, level, contains, limit) | read CloudWatch logs (workspace members) |

\* owner only.

**Adding a tool:** put the logic in a service module, then add a `@tool(...)` wrapper in `mcp.py` with a JSON-schema `properties` dict and `destructive=True`/`read_only=True` as appropriate. Add a test in `backend/tests/test_mcp.py` and update the table above. Errors are raised as `ApiError` and become `isError` tool results automatically.

**Typical admin requests and how to handle them**
- "Export the comments for OLAT": `list_workspaces` → `list_boards` → `export_board_pdf`, then give the user the `download_url`.
- "New material for next week": with a share link → `replace_board_material`; with an attached/local file → `get_upload_link(replace=true)` and hand the user the link. Say that the old state is archived.
- "Something is broken": `get_logs(level="ERROR", minutes=…)`. Each line has a `request_id`; use `get_logs(contains="<request_id>")` to see the whole request.

## Logging & debugging
- JSON lines on stdout go to CloudWatch `/aws/lambda/<stack>-api` (30-day retention). Every request logs `{"msg":"request", status, duration_ms, request_id, method, path, user_id}`.
- Use `log_event(logger, logging.INFO, "what happened", key=value)` from `muddypoints.log`. **Never log passwords, tokens or API keys** (the `/mcp/<key>` path is redacted in `handler.py`).
- Browser errors are posted to `/api/client-log` and logged with `"logger": "frontend"`.
- Unhandled exceptions are logged with a traceback (`exc`) and return a generic 500.

## Development workflow
```bash
python3 -m venv .venv && .venv/bin/pip install -r backend/requirements-dev.txt
.venv/bin/python backend/dev_server.py     # http://localhost:8787, fake AWS via moto; emails go to stdout
cd backend && ../.venv/bin/pytest          # must pass before committing; CI runs the same
```
- Tests call the Lambda handler with Function URL events against moto (`tests/conftest.py`: `Client`, the `owner` fixture, `upload()`, `make_pdf()`).
- **Every behavior change needs a test.** Keep REST and MCP behavior identical by putting logic in service modules.
- Python 3.12 on Lambda, 3.10+ locally: don't use 3.11+ only syntax or APIs.
- The only runtime dependency is PyMuPDF (`backend/src/requirements.txt`). boto3 comes with the Lambda runtime. Think twice before adding dependencies; there's no bundler for the frontend either.
- The frontend has no build: edit files directly. Use `el()` for DOM and never use `innerHTML` with user content (XSS). Keep it working on phones (students).

## Deploying
Pushing to `main` triggers `.github/workflows/deploy.yml`: pytest → `sam build && sam deploy` → write `config.js` → GitHub Pages → tag `deploy-YYYYMMDD-HHMMSS`. Pull requests only run the tests. **Everything merged to `main` is live within minutes** — real students use it.

## Working from Claude Code on the web (claude.ai/code)
Admins change the app by starting a session on this repo at claude.ai/code. In those sessions:
- Setup is automatic: the SessionStart hook (`.claude/settings.json` → `scripts/claude-web-setup.sh`) installs the test dependencies. Run tests with `cd backend && python3 -m pytest` (there is no `.venv` in the sandbox). If the hook output is missing, run the script with `CLAUDE_CODE_REMOTE=true`.
- **Work on a branch and open a pull request** — do not push to `main` directly. Describe the change for a non-programmer in the PR (what changes for staff/students, how it was tested). The user merges it on GitHub; the merge deploys.
- Run the test suite before pushing; add/adjust tests for every behavior change (see Development workflow).
- Frontend changes cannot be tested in a browser there: keep them small, reuse existing helpers (`el()`, `cogMenu()`, CSS tokens), and say in the PR what the user should click to check it after deployment.
- No AWS credentials exist in the sandbox — never try to deploy manually; CI does it. Logs/data questions go through the Muddy Points MCP connector (`get_logs`) instead.
- Rolling back from the web: open a PR that reverts the bad commit (`git revert <sha>`), see below.

## Rollback (code)
1. Find the bad change: `git log --oneline -20` and the tags with `git tag -l 'deploy-*' --sort=-creatordate | head`.
2. **Preferred**: `git revert <bad_sha>` (or `git revert <good_sha>..HEAD` for a range), then push to `main`. CI redeploys. Never force-push `main`.
3. **Emergency** (when CI on main is broken): run the workflow manually with input `ref=<deploy-tag or sha>`: `gh workflow run deploy.yml -f ref=deploy-20261117-120000`. That deploys the old code without changing `main`, so fix `main` afterwards. The next push to main deploys main again.
4. Infrastructure changes in `template.yaml` roll back through the same mechanism. The table and bucket have `DeletionPolicy: Retain`, so a bad template can't delete data. Renaming or replacing them would orphan the data, so don't.

## Rollback (data)
DynamoDB point-in-time recovery restores into a *new* table, then you switch `TABLE_NAME`. S3 is versioned (old versions are kept 30 days). Board clears and replaces archive a PDF to `archive/<bid>/` first. These are manual AWS console operations: tell the user what to do rather than attempting them.

## Conventions
- API errors: `raise ApiError(status, "snake_code", "Human message")` → `{"error": {"code", "message"}}`.
- IDs: `util.new_id()` (10 chars, no lookalikes), `util.sortable_id()` for time-ordered items.
- Timestamps: ISO-8601 UTC strings from `util.now_iso()`.
- Limits live in `config.py` (comment length 2000, upload 150 MB, 300 pages, slide long side 2000 px).
